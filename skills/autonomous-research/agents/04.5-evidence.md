# Evidence extractor

Turns the sources that report findings into a structured, quotable evidence base: for each study, what it was, how strong its design is, and what it found on each outcome, with the sentence that says so copied verbatim. Everything the paper later shows as a figure, a table, an equation or a summary number is computed from this file by a script, so the paper can say exactly where every mark on the page came from.

**Reads:** `research/sources.json`, `research/summaries.md`, `research/citations.json`
**Writes:** `research/abstracts.json`, `research/texts/*.txt`, `research/evidence.json`, `research/index.json`, `research/figures/*`, `review/evidence.md`

## When to run it

Run this stage for a literature review, a scoping review, and any paper whose argument compares what several studies found about the same outcomes. Skip it for a theoretical paper, a methods paper, or a review whose sources report no outcomes at all. A skipped stage writes nothing, and a paper without `research/evidence.json` places no evidence figure, table or equation: stage 5 checks for the file before planning any of them.

Say in `review/evidence.md` whether this stage ran and why.

## Step 1: fetch the text you are allowed to quote

```bash
python3 scripts/evidence.py abstracts research/sources.json -o research/abstracts.json
```

This asks OpenAlex for the abstract of every DOI in the source list and stores an empty string where there is none. It exits 1 when OpenAlex could not be reached for some DOIs and names them; run the same command again and it fetches only what is still missing.

A study whose abstract OpenAlex lacks, or a report with no DOI at all, can still be quoted, but only from text you actually retrieved and saved: the publisher's abstract page, or the report itself. Save that text unedited under `research/texts/`, as `<id>.txt` for a source with no DOI or as the DOI with every character outside letters, digits, `.`, `_` and `-` replaced by `_` (so `10.1038/s41562-025-02259-6` becomes `10.1038_s41562-025-02259-6.txt`). Never type a text file from memory and never paste the draft's own sentences into one. A text file is evidence; one written by the pipeline is a citation of itself.

## Step 2: write `research/evidence.json`

One entry per study that reports a finding on at least one outcome the paper is about. Sources that only frame the question, review other work or propose a policy do not go in; they stay citable in the prose.

```json
{
  "outcome_order": ["<outcome>", "<outcome>"],
  "studies": [
    {
      "doi": "<doi exactly as in research/citations.json>",
      "label": "<First author et al. year, as the paper will cite it>",
      "country": "<setting>",
      "design": "<design in a few words>",
      "tier": 3,
      "n": null,
      "type": "<intervention or exposure type>",
      "trial": "<optional: the same name on every report from one trial>",
      "outcomes": {"<outcome>": ["+", "<sentence copied from the abstract>"]}
    }
  ]
}
```

Rules for each field:

- **`outcomes`** use the same few outcome names across all studies, chosen from the paper's research question, lower case. Direction is `+` improved, `~` mixed or partly improved, `0` no change, `-` worse. The quote is the shortest span of the abstract or saved text that states that finding, copied character for character. Shorten only by choosing a shorter span, never by cutting words out of the middle.
- **`tier`** is design strength: `3` randomized, or a comparison group, quasi-experiment or event study; `2` longitudinal records, panels and pilots with before and after data; `1` cross-sectional surveys, interviews, qualitative case studies. When the abstract does not say enough to decide, use the lower tier.
- **`n`** is the sample size only when the abstract states it, as an integer. Otherwise `null`. Never estimate it.
- **`trial`** groups several papers reporting the same trial, so the trial counts once. Leave it out for a single-paper study.
- **`id`** replaces `doi` for a source with no DOI, and must match its `research/texts/<id>.txt`.

A finding you believe but cannot quote does not go in. Write the paper's sentence about it with its normal citation instead.

## Step 3: check until nothing is missing

```bash
python3 scripts/evidence.py check research/evidence.json --abstracts research/abstracts.json --texts research/texts -d research/citations.json
```

It validates every field and then looks for every quote, verbatim, in its own source text, ignoring only Unicode form, quote and dash style and runs of whitespace. It exits 1 and lists each quote it could not find, each study whose DOI is not in the citation database, and each study with nothing to quote from. Fix each one by copying the real span or by removing the claim. Do not move on while it exits nonzero.

## Step 4: compute the index and draw the figures

```bash
python3 scripts/evidence.py index research/evidence.json -o research/index.json
python3 scripts/evidence.py figures research -o research/figures
```

`index` computes, per outcome, the design-weighted evidence mass *M*, the evidence index *S* between -1 and 1, the leave-one-out range of *S*, the number of reports, and how many come from tier 3 designs. `figures` draws the evidence profile with the source timeline, the evidence map and the source flow as SVG, writes the study-characteristics table and the evidence ledger, and writes their captions. Every number in all of them is read from the files above.

These numbers go into the paper exactly as `research/index.json` states them, rounded to two decimals. Never type one from memory and never round one differently in two places.

## What the index is, and what it is not

The index summarizes the direction and design weight of reported findings. It is descriptive. It is not a meta-analysis, not a pooled effect size, and not a measure of how large an effect is, and the paper must say so where it introduces it. A high *S* on a small *M* means a few favorable reports, not strong evidence; the paper reports both numbers together, always.

## Done when

- `research/evidence.json` exists and `evidence.py check` exits 0.
- `research/index.json` and every file in `research/figures/` were produced by the two commands in step 4 after the last edit to `research/evidence.json`.
- `review/evidence.md` records whether this stage ran, the output of the last `check` and `index` runs, and names any study left out because nothing about it could be quoted.
